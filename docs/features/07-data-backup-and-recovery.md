# 数据、备份与恢复

## 数据位置和格式

正常运行的数据文件是：

```text
%APPDATA%\StudyFlow\studyflow.sqlite
```

测试脚本使用 `.cache/` 下的独立目录，不应操作正常用户数据库。当前 schema 版本为 7，使用 Electron 内置 Node 的 `node:sqlite`，没有额外 SQLite npm 原生模块。

## schema v7 内容

| 表 | 主要内容 |
| --- | --- |
| `projects` | 项目 ID 和名称 |
| `tasks` | 项目归属、标题、完成状态、预计分钟、累计有效学习时间 |
| `settings` | 定时专注分钟、白名单、会话/全天活动记录开关、常用计时模式、番茄参数及 AFK 阈值 |
| `sessions` | 会话状态、修订号、摘要、已结算时间和恢复收据 |
| `timer_slices` | 按日期拆分的计时片段及有效/AFK/未知时间 |
| `activity_intervals` | 可选保存的 active/AFK/unknown 应用活动区间 |
| `ambient_activity` | 不依附专注会话的全天活动区间，按日期拆分 |
| `daily_reviews` | 每日复盘 JSON 文本；兼容旧纯文本 |
| `daily_plans` | 每日计划快照 JSON |
| `app_categories` | 标准化应用名到手动分类的映射 |
| `import_batches` / `imported_tasks` | 导入摘要、任务键映射和重复导入记录 |
| `task_details` / `project_order` | 任务标签、依赖、排序、归档和项目顺序 |
| `daily_checkins` | 每日独立打卡 |
| `daily_plan_reminders` | 按本地日期去重的提醒记录、操作令牌、稍后时间；不存任务正文 |

每日提醒开关和 HH:mm 时间保存在 `settings.preferences.planReminder` 中。普通计时设置保存时保留提醒配置。

数据库开启外键、3 秒 busy timeout、同步落盘和 secure delete。

## 升级备份

打开 v1 至 v6 数据库时，StudyFlow 会在执行对应升级前使用 SQLite `VACUUM INTO` 创建一致性备份。备份文件位于原数据库旁，例如：

```text
studyflow.sqlite.<随机UUID>.v2.sqlite
studyflow.sqlite.<随机UUID>.v2.sqlite.sha256
```

程序会刷盘、计算 SHA-256、重新读取核对，并在只读模式运行 `integrity_check` 和版本检查。任何步骤失败都会中止启动；迁移 DDL 在事务中执行，失败回滚，不通过清空数据库解决。

启动升级时保留输入版本的备份，再依次迁移到 v7；不为同一次启动中的中间版本重复备份。已经是 v7 时不会重复创建升级备份。高于 v7 的未知数据库会被拒绝，原数据不改动。

升级备份可能包含升级时已有的历史数据。日常“删除历史”不会修改这些只读恢复材料，因此敏感数据清理时需要同时评估备份文件。

## 检查点和原子性

会话检查点带递增修订号和 SHA-256 摘要。完全相同的重试直接接受；旧修订、同修订不同内容、已经停止/中断的会话或任务归属变化会被拒绝。

片段替换、活动区间替换和任务累计差额在一个事务内完成。任何写入失败都会整体回滚，避免历史成功而累计失败，或累计成功而历史缺失。

计时检查点只替换近期可修正尾段，已保存前缀保留在数据库；内存保留累计汇总和 AFK 阈值加 90 秒余量。全天轨道使用独立运行 ID 和单调时间边界替换尾段，保存成功才释放。保存失败保留原缓冲，允许重试。

## 重启恢复

启动时，数据库中未处于 `stopped` 或 `interrupted` 的会话统一标为 `interrupted`。程序保留最后成功检查点中的历史和任务累计，但不会恢复旧单调时钟，也不会自动继续旧会话或补算停机时间。用户需开始新会话。

崩溃或断电可能丢失最后成功检查点之后、最多约 30 秒的未提交状态。普通退出会尝试停止并保存；如果最后保存失败，应用会取消退出并显示错误，让内存中的待保存状态仍有重试机会。操作系统强制终止无法保证执行此流程。

## 备份恢复与降级

当前没有图形化恢复按钮。手工恢复应在 StudyFlow 完全退出后进行，并先另存当前 `studyflow.sqlite`。校验 `.sha256` 后，选择与目标程序兼容的升级前备份（例如 `.v5.sqlite` 或 `.v6.sqlite`）替换主数据库，再运行兼容版本。备份后缀对应备份时的 schema，不是应用版本号；保留的 v1—v6 备份应分别交给支持该版本的程序。

不支持 schema v7 的旧版不能直接打开当前数据库。降级不能只替换 exe；应退出应用、另存 v7 数据，再明确恢复目标版本兼容的升级前备份。升级前备份只包含当时的数据，升级后的计划、复盘、历史和提醒记录不会出现在旧备份中；安装器不会自动回滚数据库。

v7 增加每日提醒账本。迁移、备份校验与拒绝不兼容数据库的回归可通过[开发与验证指南](09-development-and-verification.md)中的命令复现；应用回退不能替代数据库兼容性检查。
