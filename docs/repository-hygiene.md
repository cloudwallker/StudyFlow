# 仓库文件与公开文档约定

本仓库保留从源码安装、运行、构建和测试 StudyFlow 所需的材料。整理文件时保留本地数据与用户已有工作，不以清理为由自动改写既有 Git 历史。

## 公开保留的文件

- `src/`、`desktop/`、`native/`、`plugin/`：独立应用及仍被测试和构建使用的旧插件源码。
- `tests/`、`scripts/`：回归测试、构建、安装、打包与可重复验证脚本。
- `package.json`、`package-lock.json`、`tsconfig.json`：npm 依赖与构建配置。
- `examples/`：实际使用的 JSON/XLSX 导入模板，构建脚本会复制它们。
- `third-party/`、版权文件头及[源码来源说明](source-reuse.md)：上游来源、固定版本与许可材料。
- 英文及中文 README、共享 AGENTS.md、功能指南、格式说明和产品路线。

## 仅留本机的文件

依赖、构建目录、便携包、下载缓存、测试数据库、日志、本地运行时、真实配置、私人证书和工具登录状态不进入源码仓库。`local-runtime/` 可能含浏览器配置、登录状态和 Cookie 数据库，不能上传。

AI 对话、临时实施计划、Superpowers 规划、交接提示、内部任务表及本地执行记录保留在本机。需要公开的产品能力、架构、格式及验证范围整理为独立使用文档，不依赖这些过程文件。

不按 JSON/TXT/MD 等扩展名或 backup/private 等名称片段整体忽略。数据库备份使用实际目录或后缀匹配，避免误伤备份功能源码与说明。`.gitignore` 不会取消已有文件跟踪，也不会移除历史内容；取消跟踪时保护本地副本。

共享工具配置逐项核实其产品用途，个人 sessions、auth、history、logs 和机器专属路径排除。通用 Windows 系统路径及明确虚构的测试路径可保留；真人路径使用相对路径或占位符。

## 配置、隐私与署名

应用设置保存在本地 SQLite，没有必需的模型凭据或 `.env`。环境示例只使用手写占位符，不把真实配置复制为示例。开发环境说明见[构建指南](features/09-development-and-verification.md)。

公开 CA 证书与私钥区分检查；测试令牌结合用途和真实内容判断。不得公开密码、令牌、私钥、凭据、真实任务或采集历史。许可证、原贡献者署名和用户授权公开的 GitHub 身份保留。

## 发布前检查

1. 核对候选文件、完整暂存树及本次将推送的提交范围，确认没有额外文件或过程材料。
2. 检查秘密、私人数据、个人路径、大文件及图片实际内容；只报告问题位置和类别，不输出秘密。
3. 确认 Git 作者和提交者属于已核实的用户 GitHub 账户，优先使用已验证的 noreply 邮箱。
4. 检查公开文件清单中的相对链接、构建入口、依赖和示例；本机存在但未发布的文件不能作为有效链接。
5. 按变更执行相关回归、lint、构建及包校验，记录实际范围；自动化不替代人工系统场景验收。

源码与分发附件分别审查。便携包从已检查的源码构建，不压缩整个工作区；本地打包成功不等于已公开发布。
