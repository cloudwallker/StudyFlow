# StudyFlow JSON/XLSX 导入格式指南

适用于 `0.5.0-local`。文件描述待执行任务与每日计划，不包含实际学习时长、应用历史、复盘或完成状态。StudyFlow 在本机解析、预览并经用户确认后保存，不调用模型 API 或上传本地数据。

## 使用流程

1. 在学习工作台点击“导入计划”，或展开“添加任务 / 导入计划”中的“导入已有学习计划”。
2. 选择 UTF-8 JSON 或 XLSX 文件，也可粘贴 JSON 或完整 JSON 代码块。使用[JSON 模板](../examples/studyflow-plan.json)或[Excel 模板](../examples/studyflow-plan.xlsx)填写内容；两种模板映射到相同模型。
3. 检查项目、任务、每日分钟数、日期范围、未安排日期任务及增删改差异。确认前不创建数据，取消不写入。
4. 同名项目唯一时复用；存在多个同名项目时明确选择。已有日计划默认合并，整日替换需要逐日勾选。修改选择或第 1 天日期后重新预览。
5. 校验通过后点击“确认导入”。有日期的计划导入后打开计划首日，点击“今天”回到当天；每日计划与复盘的使用见[功能指南](features/06-daily-plan-and-comparison.md)。

文件最大 1 MiB，最多 1000 个任务和 5000 条计划。每天最多 500 项、1440 分钟，合并时计入已有安排。只保存规范化内容的 SHA-256、导入时间与外部任务键映射，不保存原文件或路径。

## JSON v1

JSON 使用 UTF-8，顶层仅包含 `schemaVersion: 1`、`tasks` 和 `plans`。数组必填，tasks 至少包含一个任务；只创建任务时使用 `plans: []`。不接受额外字段，文本首尾空格会去除。

| 数组 | 字段 | 规则 |
| --- | --- | --- |
| tasks | taskKey | 文件内唯一非空标识，最长 80 字符，供 plans 引用 |
| tasks | project | 项目名称，最长 80 字符；空字符串表示未分配项目 |
| tasks | title | 非空标题，最长 200 字符 |
| tasks | estimateMinutes | 1—240 的整数，单位分钟 |
| plans | date | 有效的 YYYY-MM-DD 本地日历日期，不转换 UTC |
| plans | taskKey | 引用本文件 tasks 中存在的任务 |
| plans | minutes | 1—1440 的整数；同日同一任务不可重复 |

只分配日期与分钟，不增加小时级时间槽、任务依赖或排程算法。例如：

```json
{
  "schemaVersion": 1,
  "tasks": [
    { "taskKey": "reading-001", "project": "阅读计划", "title": "阅读第一章并整理笔记", "estimateMinutes": 45 }
  ],
  "plans": [
    { "date": "2026-10-03", "taskKey": "reading-001", "minutes": 45 }
  ]
}
```

## 日期与每日打卡

明确的 `plans.date` 优先。任务没有 plans 安排时，标题开头的有效 YYYY-MM-DD 可以补充日期；“第1天”“第一天”“Day 1”“1｜”等天数前缀可结合第 1 天日期推导。不会把“阅读1篇论文”“1.5小时”当作学习天数。

同项目已有天数与明确日期时，可推导日期锚点；没有锚点时填写“第 1 天日期”并重新预览。已有日期不一致会提示修正文件，不静默选择锚点。推导只生成预览，确认才保存；无法安排的任务显示“未安排日期”，可在每日计划中手动安排。缺少 plans 条目与非法 plans 日期不同：已填写的无效日期会被拒绝。

每日打卡按日期＋任务独立保存。同一 taskKey 可以安排多天，用于重复练习；每天不同学习内容使用不同 taskKey。往日未完成安排可以补打卡，不改原日期，也不补造实际学习时长。全部任务中的整体完成状态与当日打卡分开。

## 去重、任务更新与确认

相同规范化内容重复导入会跳过，格式缩进或 UTF-8 BOM 不影响识别。数组重排不保证视为相同内容，外部任务键仍用于防止重复创建；不要按标题推断任务身份。

相同 taskKey 的标题、项目或预计分钟改变时，默认列为冲突。逐项选择“更新已有任务”、重新预览前后差异并确认后，只修改这些字段，保留完成状态、累计用时、标签、依赖和历史。已删除任务须先恢复。

已有日计划默认合并；同日同一任务更新计划分钟。整日替换不能移除已打卡安排。预览涉及的数据发生相关变化时，必须重新预览；后台累计时间及无关任务变化不会直接使预览失效。

确认使用一次性预览令牌，在单一 SQLite 事务中写入项目、任务、计划与导入记录，错误整体回滚。导入前如有未保存的每日计划，先保存或明确放弃，再重新检查预览。复盘草稿与计划草稿分别保护。

## XLSX 模板

必须且只能包含以下三个工作表，表头位于第 1 行并保持顺序：

- `meta`：表头 schemaVersion，A2 为数字 1。
- `tasks`：表头 taskKey, project, title, estimateMinutes，每行一个任务。
- `plans`：表头 date, taskKey, minutes，每行一个安排。

日期使用文本 YYYY-MM-DD，分钟填写整数；空数据行跳过。可读取常见 Transitional SpreadsheetML、内联文本和共享字符串，XML 必须使用 UTF-8。

不使用公式、合并单元格、宏、超链接、外部关系或嵌入对象；不支持 XLS、XLSM、任意表头、Excel 日期序列值、加密表、Strict OOXML、ZIP64 或分卷 ZIP。

工作表行号最多 10000；压缩文件最多 1 MiB，内部最多 128 个文件，单文件解压最多 4 MiB，合计最多 8 MiB；规范化后的 JSON 仍须满足 1 MiB 限制。

## 在外部工具生成文件

可以手工填写模板，也可以向自己选择的外部工具描述目标、日期及每天可用时间。只提供生成计划所需的信息，下载后检查内容，StudyFlow 仍要求预览与明确确认。外部工具的收费和数据处理规则由用户自行选择。

可使用以下通用请求模板：

> 请根据我的目标和可用时间生成 StudyFlow JSON 计划文件，文件名 studyflow-plan.json。若能生成文件，请提供下载；否则提供可保存为 UTF-8 JSON 的完整内容。
>
> 顶层仅包含 schemaVersion: 1、tasks、plans。tasks 每项包含唯一 taskKey、project、title、estimateMinutes（1—240 整数）；plans 每项包含明确 date（YYYY-MM-DD）、对应 taskKey、minutes（1—1440 整数）。同日同一任务不重复，每日总分钟不超过我的可用时间，也不超过 1440 分钟。不同学习内容使用不同 taskKey，重复练习可把同一 taskKey 安排多天。不要写完成状态、累计用时或其他字段。
>
> 我的目标：[填写]；开始日期：[填写]；每天可用分钟：[填写]；已有安排和限制：[填写]。

需要 Excel 时，要求按三个工作表与规定表头生成 XLSX，日期为文本、分钟为整数、单元格为静态值。
